Flujo del Proyecto Hematica

Mapa visual de como viajan los datos desde React, pasan por Django REST Framework, se validan con serializers, llegan a modelos Django y terminan guardados en MySQL.

1. Flujo general de datos

Esta es la idea principal: el usuario escribe datos en una pantalla, React los manda con fetch(), Django los recibe, valida y guarda en MySQL.
Usuario Usa formularios, botones y tablas en el navegador.
→
Frontend React frontend/src Pantallas: Login, Mascotas, Solicitudes, Resultados.
→
fetch() Manda JSON o FormData a la API.
→
Backend Django backend-django Recibe la peticion HTTP.
→
Serializer + Modelo Valida, convierte y prepara datos.
→
MySQL Base: hematica_db

2. Carpetas principales

frontend/src/App.js Controla rutas, login activo y rol del usuario.
frontend/src/pages Pantallas del sistema: Login, Mascotas, Empleados, Estudios, Solicitudes y Resultados.
backend-django/hematica_project Configuracion global de Django, base de datos y rutas principales.
backend-django/apps Modulos de backend: usuarios, pacientes, empleados, estudios y solicitudes.
docker-compose.yml Levanta MySQL 8 y Django. MySQL guarda la base hematica_db.

3. Login

Login.jsx El usuario escribe correo y contraseña. frontend/src/pages/Login.jsx
→
POST /api/v1/auth/login/ React manda correo y password con fetch().
→
usuarios/urls.py La ruta apunta a LoginView.
→
LoginView Busca al usuario por correo y revisa la contraseña con check_password().
→
tabla usuario Django consulta correo, password cifrada y tipo de usuario.
→
JWT + UsuarioSerializer Si todo esta correcto, crea token y devuelve datos del usuario.
→
localStorage + App.js Guarda token, detecta rol y muestra rutas segun admin, veterinario o usuario.

4. Registro de cliente

Login.jsx en modo registro Captura nombre, correo, telefono y contraseña.
→
POST /api/v1/auth/register/ Manda id_tipo_usuario: 1 para cliente.
→
RegisterSerializer Cifra la contraseña con make_password().
→
tabla usuario Guarda el usuario nuevo.
→
tabla cliente Si el tipo es cliente, crea automaticamente su perfil de cliente.

5. Mascotas / pacientes

MisMascotas.jsx o MisPacientes.jsx El usuario/admin llena datos de la mascota.
→
POST /api/v1/pacientes/ Manda nombre, sexo, edad, raza, cliente, peso y anamnesis si aplica.
→
PacienteViewSet Recibe la peticion CRUD.
→
PacienteSerializer Valida y convierte JSON a objeto Django.
→
tabla paciente Guarda la mascota ligada a cliente y raza.

Cartilla PDF

FormData Archivo en campo cartilla_pdf.
→
PATCH /pacientes/{id}/subir_cartilla/ Valida PDF y maximo 10 MB.
→
media/cartillas/ Guarda el archivo y la ruta en la tabla paciente.

6. Empleados y veterinarios

Empleados.jsx Admin crea personal del laboratorio.
→
1) POST /api/v1/auth/register/ Primero crea el usuario base.
→
tabla usuario Guarda nombre, correo, telefono, password cifrada y tipo.
→
2) POST /api/v1/empleados/ Crea el empleado ligado al usuario.
→
tabla empleado Guarda clinica, telefono, direccion y tipo de empleado.
→
3) POST /api/v1/veterinarios/ Solo si el empleado es veterinario.
→
tabla veterinario Guarda CURP y cedula.

Asignacion de clientes a veterinarios

Empleados.jsx Admin asigna cliente.
→
/veterinarios/{id}/asignar_cliente/ Crea la relacion.
→
tabla veterinario_cliente Relacion muchos a muchos.

7. Catalogo de estudios

Estudios.jsx Admin crea o edita estudios y precios.
→
POST / PUT / DELETE /api/v1/estudios/ Manda nombre y precio.
→
CatalogoEstudioViewSet CRUD generado por Django REST Framework.
→
CatalogoEstudioSerializer Valida campos.
→
tabla catalogo_estudio Guarda estudio y precio.

8. Solicitudes

Solicitudes.jsx Cliente selecciona mascota y estudios.
→
POST /api/v1/solicitudes/ Crea solicitud con estado pendiente.
→
tabla solicitud Guarda paciente, estado, fecha y notas.
→
POST /api/v1/solicitud-estudios/ Se ejecuta una vez por cada estudio elegido.
→
tabla solicitud_estudio Une solicitud con catalogo de estudios.

Cambio de estado

Boton de admin/veterinario Recibir, procesar, cancelar o finalizar.
→
PATCH /solicitudes/{id}/cambiar_estado/ Valida estado y guarda motivo si se cancela.
→
tabla solicitud Actualiza estado y motivo_cancelacion.

9. Resultados y PDF

Solicitudes.jsx Admin/veterinario finaliza y crea resultado.
→
POST /api/v1/resultados/ Crea resultado con veterinario, fecha, observaciones y reporte.
→
tabla resultado_estudio Guarda resultado clinico.
→
perform_create() Cambia solicitud a finalizado y crea historial clinico.
→
tabla historial_clinico Guarda expediente relacionado al paciente.

Formulario de bioquimica

ResultadoEstudio.jsx Admin llena analitos e interpretacion.
→
PATCH /resultados/{id}/ Actualiza reporte_clinico como JSON.
→
tabla resultado_estudio Guarda observaciones y reporte.

Generacion y subida de PDF

html2canvas Captura el formulario visual.
→
jsPDF Genera PDF comprimido.
→
FormData Campo archivo_pdf.
→
PATCH /resultados/{id}/subir_pdf/ Valida que sea PDF y menor a 10 MB.
→
media/resultados/ Guarda archivo y ruta en archivo_pdf.

10. Tablas de la base de datos

Tabla Que guarda Archivo modelo
tipo_usuario Roles: cliente, veterinario, admin. apps/usuarios/models.py
usuario Nombre, correo, password cifrada, telefono y tipo. apps/usuarios/models.py
cliente Perfil de tutor ligado a usuario. apps/pacientes/models.py
especie / raza Catalogos para clasificar mascotas. apps/pacientes/models.py
paciente Mascotas, edad, peso, raza, dueño, cartilla. apps/pacientes/models.py
empleado / veterinario Personal, clinica, telefono, cedula y CURP. apps/empleados/models.py
veterinario_cliente Clientes asignados a cada veterinario. apps/empleados/models.py
catalogo_estudio Estudios disponibles y precio. apps/estudios/models.py
solicitud Solicitud de estudio de un paciente. apps/solicitudes/models.py
solicitud_estudio Relacion entre solicitud y estudios elegidos. apps/solicitudes/models.py
resultado_estudio Reporte clinico, observaciones, veterinario y PDF. apps/solicitudes/models.py
historial_clinico Expediente generado por paciente. apps/solicitudes/models.py

→

→
3. Cliente registra mascotaMisMascotas.jsx manda paciente.
→
4. Se guarda pacienteTabla paciente.
→
5. Cliente crea solicitudSelecciona mascota y estudios.
→
6. Se guardan solicitud y estudiosTablas solicitud y solicitud_estudio.
→
7. Admin/veterinario procesa muestraCambia estados y crea resultado.
→
8. Se guarda resultado e historialTablas resultado_estudio e historial_clinico.
→
9. Admin llena formulario clinicoSe guarda JSON en reporte_clinico.
→
10. Se genera y sube PDFArchivo en media/resultados/.
→
11. Cliente descarga resultadoReact muestra el link del PDF.
